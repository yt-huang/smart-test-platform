# Runtime delivery: implemented and locally verified

Input: `docs/implementation-handoff.md` v1, commit db60c88. Actual implementation agent: Codex child `/root/runtime`; isolated branch `codex/platform-runtime`. Scope: `agent/`, `cli/`, `examples/`.

Implemented outbound browser registration, real launch/close capability probes, heartbeats, reconnect after cleanup, task deduplication, resource exclusion, cancellation and execution deadlines. Structured approved web cases run in fresh Playwright contexts, with owned multipart screenshot/video/trace/log uploads. Metadata validation rejects unsupported actions/frameworks. The private network flag is explicit for trusted local targets. Bootstrap creates and persists an AgentKey once; restarts/reconnects reuse it. CLI selects approved suites or plans, authenticates, polls, prints the hash-route report URL, exports JUnit, and returns the specified exit codes. Docker pins official Playwright `v1.64.0-noble` matching the npm package, uses `pwuser` and writable `/agent-data`. Configure a fixed host fingerprint or container hostname for persistent key ownership.

Optional Android/Appium adapter uses actual ADB enumeration, trusted `APPIUM_URL` and explicitly configured package/activity or Chrome. Only a healthy service without conflicting/unknown sessions, successful W3C UiAutomator2 create/delete, invalid-session verification and actual ADB force-stop/data reset permit an IDLE resource. Every case receives a fresh reset session. Structured click/fill/text/visibility/screenshot actions use W3C endpoints; Chrome also supports goto. Mobile evidence is device screenshots and execution logs. No arbitrary portal scripts or shell commands are supported. Lost session creation responses, failed cleanup and lost devices quarantine the resource. Browser quarantine survives reconnect within a running Agent.

Wire additions agreed with backend: assigned `run.deviceId` is the registration target ID; `executionTimeoutSeconds` is supplied. Platform sends `{type:"cancel",taskId,reason}`. Browser probes send `status:"IDLE",cleanupOk:true`; heartbeat resources carry current state. Completed `done` cleanup is true only after verified context and browser closure.
