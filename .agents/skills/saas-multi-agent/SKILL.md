# SaaS 多 Agent 协作

把一个明确功能推进到约定的交付结果，减少重复解释、重复实现和合并返工。职责与模型分别选择：默认 Codex 主控协调，Codex 子 Agent 实现，独立上下文 Agent 验收；设计按任务需要单独分派。Kimi 是可选执行者，同一模型的多个真实 Agent 也能完成协作。

## 入口与阶段

先读取实际项目规则和与任务相关的代码，确认工作目录、目标功能及现有成果；不要重建已有系统或每次阅读全部文档。

支持用户指定 `prepare`（需求与任务包）、`design`（交互／视觉）、`implement`（代码实现）、`verify`（独立验收）、`full`（完整流程），并可指定实现者。默认实现者为 Codex 子 Agent。这些是自然语言约定，不是内置 CLI 参数。只执行指定阶段；方向探索走 prepare。明确功能开发请求且未限定阶段时执行完整流程，不以只交付文档代替实现。

按需阅读 [运行与接入](references/runtime.md)：需要调度细节、首次接入或真实跨模型执行时使用。已有可用配置直接复用；全 Codex 协作无需检查 Kimi 登录或配置。

## 职责与交接

- 主控 Agent：简短 PRD、行为场景、接口／数据契约、必要技术决定、任务分配与集成；统一维护共享规格和状态。
- 设计 Agent：先做核心流程和代表页面，复用组件与 tokens；明确加载、空、失败、成功、禁用和响应式。需要 Figma 时使用真实连接，按 [设计交接](references/design.md) 提供可实施输入。
- 实现 Agent：可用 Codex 或 Kimi，读取指定版本任务包，实现约定代码与测试，交付实际差异／提交及检查结果。文件与接口独立时可分为前端、后端或不同模块 Agent。
- 独立上下文验收：使用可用的隔离上下文子代理，或用户指定的新会话，根据规格、UI 与实际 diff／运行结果核对业务和视觉，返回可复现发现；原实现者修复。不为内部审查擅自创建用户可见新聊天。

每个功能对应一个 OpenSpec change。全局 PRD 保存目标，delta specs 保存精确行为，design.md 保存技术决定，tasks.md 保存实施任务；视觉信息使用 ui-handoff.md。只补充本次改变的内容，已有事实用路径引用，避免重复生成整套文档。OpenSpec 集成存在时复用其实际技能，不存在时先按已有项目组织工件并说明接入状态，勿伪称已经初始化。

用 [交接模板](assets/handoff.md) 生成只含相关输入的任务包：输入版本、真实模型身份、工作目录、任务／文件范围、验收条件、真实检查命令和结果路径。不得把示例命令或尚待填写的设计节点当作已就绪输入。

用户明确要求多 Agent 时，实际分派可验收子任务并等待结果，由主控核对与集成；只列角色或把同一段回答分成多个角色不算协作。给子 Agent 最少必要上下文与明确交付条件。阶段为 prepare/design 时，子任务可为规格检查或设计；不要越阶段实现。缺少实际调度能力时说明缺口。

## 效率与执行边界

接口就绪后可先做后端，UI 就绪后推进前端；按功能滚动设计。存在独立工作才并行。同一阶段每个文件明确一个写入负责人；并行实现使用隔离分支／worktree，统一验证集成结果。

设计角色默认交付设计与组件用法；实现角色完成生产代码。若设计 Agent 也编写生产 UI，明确展示层／公共组件归属，业务实现 Agent 复用并接业务，避免重写已完成代码。角色可以全由 Codex Agent 承担，也可按用户要求混用工具。

Codex 协作使用实际可用的子 Agent 调度工具，保留任务标识、结果和验证证据；对独立任务并行分派，对依赖任务等前置产物就绪。用户选择 Kimi 时才调用其真实 CLI／网页／API，并核验执行身份；不能把 Codex 子 Agent 改名后当作 Kimi。工具缺失时完成仍可推进的工作，说明具体缺口，不悄悄替换用户明确要求的工具。

用户已确定的范围和约定直接执行。Figma、合并、发布等操作遵循该任务已有授权；skill 本身不新增外部写入授权。只对会改变业务结果或重大实现取舍的缺失信息提问，独立工作继续。

## 验收与完成

测试从行为场景推导，检查深度随风险调整。权限、租户、数据、计费等边界检查负向与失败情况；低风险小改不强制完整设计和多角色流程。

实际执行相应检查，记录输入版本、提交、命令、结果及未验证项。OpenSpec validate、Agent verify、任务勾选和 CLI 退出成功均不能替代程序验收。只验收阶段时可运行检查与只读审查，不代替实现者修复代码。

需求冲突由协调者更新工件并记录受影响任务；不得通过放宽规格或删测试让检查通过。修复无进展时依据证据调整方法、范围或执行者，避免重复盲改。

交付汇总实际成果、阶段状态、验证与剩余事项。实现报告为 implemented；verified 需要验收证据；integrated 需要检查集成版本。完成约定交付后再同步／归档规格，发布按实际任务范围进行。记录人工投入、交接、返工与可观测费用，用真实任务迭代流程。
