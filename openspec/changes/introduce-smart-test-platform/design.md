# Design: introduce-smart-test-platform

## 总体架构

五层架构，AI 引擎作为横切能力纵贯全层（架构图见报告 `charts/target-architecture.png`）：

```
L5 接入层   ：统一门户 / OpenAPI·CLI / CI 插件(Jenkins·GitLab) / IM 通知(飞书·钉钉)
L4 能力层   ：用例与计划管理 / UI 自动化(Web·App) / 接口测试 / 兼容性矩阵 / AI 用例生成与自愈
L3 调度执行层：任务分片·优先级调度 / 执行引擎(Playwright·Appium·Maestro) / AI Agent 执行(Midscene) / 证据采集
L2 资源层   ：自建真机池(Sonic) / 公有云真机(优测·WeTest) / 浏览器网格(Selenium Grid·Playwright 容器) / 模拟器
L1 基础设施层：K8s / 对象存储(截图·录像·trace) / 消息队列 / 日志监控
AI 引擎（横切）：私有化视觉模型(Qwen3-VL/UI-TARS) —— 视觉定位、用例生成、失败归因、自愈
```

## 关键设计决策

### D1：执行引擎"双轨制"而非单框架
- **决策**：Web 新项目用 Playwright，存量 Selenium 套件不强迁；移动端以 Appium 为底座，Maestro 作为冒烟补充。
- **理由**：Selenium 中型套件迁移需 2–4 个月，强迁 ROI 为负；Appium 是所有商业云真机与开源设备农场的共同协议，放弃它会丧失资源层互换性。
- **代价**：需维护两套 Web 引擎的公共组件库，通过统一 Page Object 规范与共享测试数据层控制。

### D2：资源层统一抽象"执行目标（Execution Target）"
- **决策**：测试任务只声明所需能力（`platform=android, version=14, brand=xiaomi` 或 `browser=webkit`），调度层路由到自建机池 / 云真机 / 浏览器网格。
- **理由**：自建与商业云的混布是长期状态；抽象层使"核心回归走自建、长尾兼容走云"的策略可配置化，且供应商切换只影响适配器。
- **实现**：调度层为每类资源池实现 Adapter（Sonic OpenAPI / 优测 OpenAPI / Selenium Grid），统一排队、心跳、占用锁与回收。

### D3：AI 引擎私有化 + 人机协同门禁
- **决策**：AI 能力基于 Midscene.js + 私有化部署 Qwen3-VL/UI-TARS；AI 生成用例进入"待审核"状态，人工通过后入库；自愈变更生成 diff 供评审。
- **理由**：商业大模型外传数据有合规风险；行业平均脚本失效率约 30%，UI-TARS 在 >12 步任务上误判率上升，无人值守不现实。
- **代价**：需 1 台 GPU 推理节点（Qwen3-VL-8B 级别即可起步）；审核流程增加用例入库延迟（可接受，回归门禁链路不受影响）。

### D4：平台层基于 MeterSphere 二次开发，不自研
- **决策**：测试管理/接口测试/报告用 MeterSphere 开源版，UI 测试与设备调度通过插件与自研调度服务集成。
- **理由**：覆盖 80% 通用需求，Docker 部署、插件市场可接 Jenkins/Jira/禅道；自研仅投在差异化部分（资源调度 + AI 引擎集成）。
- **风险**：v3.x 开源版剥离了 UI 测试与性能测试——若其企业版报价不合理，UI 测试模块改为自研薄层 + Allure 报告。该决策点在 P2 启动前完成评估。

### D5：分阶段灰度，每阶段可独立验收
- **决策**：严格按 P0→P3 推进，每阶段在 1–2 条业务线验证后横向推广；AI 能力（P3）不进入门禁链路直至试点指标达标。
- **理由**：平台工程失败的主因是"大爆炸式"上线；CNCF 平台成熟度模型强调以内在拉力（平台好用，团队自发采用）替代行政强制。

## 数据与证据流
- 每次执行产出：截图、录像、trace（Playwright trace / Appium 日志）、性能采样（CPU/内存/FPS）、结构化结果（JUnit XML + Allure）。
- 全部证据入对象存储，平台侧保留索引；失败用例自动聚合 flaky 标记（同一用例非代码变更导致的间歇失败 >5% 即隔离）。

## 安全与合规
- 敏感业务用例打标，调度层强制路由至自建机池；云真机仅执行脱敏环境用例。
- 视觉模型私有化部署于内网 GPU 节点；禁止将含业务数据的截图发送至外部模型 API。
- STF/Sonic 安全模型假设内网可信，部署时置于独立 VLAN，经网关鉴权访问。
