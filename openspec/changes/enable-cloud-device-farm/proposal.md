# Proposal: enable-cloud-device-farm（状态：BACKLOG，未启动）

## 状态说明

本变更为**预留变更**：当前公司兼容性测试要求不高，App 测试仅使用本地真机（2–4 台）+ Android 模拟器，不对接云真机。本提案仅登记触发条件与启用路径，**待触发条件满足后再进入 propose → apply 流程**。

## Why（未来为什么要做）

当本地设备覆盖不住用户机型分布时，会出现"特定机型才复现"的线上缺陷、发版前借机排队等信号。届时需要公有云真机（国内优先腾讯优测按需计费，游戏/性能场景选 WeTest）提供 10+ 机型的一键兼容回归，预估成本 ¥0.5–2 万/年。

## 触发条件（满足任一即启动评估）

- 线上出现"特定机型才复现"的兼容缺陷 ≥2 次/季度
- 发版前手工借机/排队超过半天
- 需要覆盖鸿蒙机型
- 出海或用户机型长尾明显扩大

## What（启用时做什么）

1. 供应商评估与开通账号（优测 / WeTest 二选一，PoC 跑 10 款机型主链路）
2. 填写 `devices.yaml` 的 `cloud` 档（hub_url / 凭证走环境变量 / device_query 声明式机型需求）
3. 执行 `run --provider=cloud` 验证 Top 机型矩阵回归
4. 把"发版前云端兼容回归"加入发版流程与门禁
5. 云真机用量纳入成本月报（按业务线归集）

## 前提约束（当前阶段必须遵守，否则届时无法平滑开通）

- 所有用例仅用 WebDriver/Appium 标准协议；设备信息全部外置在 `devices.yaml`，禁止硬编码型号/udid
- 用例只声明能力（platform/version/brand），不点名具体设备
- 执行记录必须带设备指纹（型号/系统/provider），保证本地与云结果可汇入同一报告
- 禁止引入任何厂商私有 DSL/capability 扩展

## 不做什么

- 不自建机池（设备折旧与运维对小团队不划算）
- 不提前采购套餐囤积（按需计费）
- 不因接云而改动任何存量用例
