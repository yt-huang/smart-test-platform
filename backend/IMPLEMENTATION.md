# Backend implementation report

Input: implementation-handoff v1, base db60c88. Implementer: actual Codex backend child agent, branch `codex/platform-backend`, isolated worktree. Scope: `backend/` only.

Implemented Spring Boot 3.5.15 / Java 21 central API, PostgreSQL production profile and H2 file local profile. JDBC stores workspace-scoped documents in a composite-key table. Passwords use BCrypt; opaque session and AgentKey secrets use secure random bytes and SHA-256 storage. Admin bootstraps from `PLATFORM_ADMIN_PASSWORD` only; startup rejects missing/short passwords (12 characters minimum, 72 UTF-8 bytes maximum). Environment password seeds the initial account and does not overwrite existing database users.

Implemented four-role authorization; case structured-step validation, mandatory human approval and revision history; immutable case snapshots in runs; plans; priority/FIFO queue and queue/execution timeouts; per-resource leases; outbound WS registration, host/key binding, revocation, assignment ownership, idempotent completion, heartbeat resource discovery, quarantine and explicit cleanup proofs. Initial discovery cannot grant `trusted`; administrators assign trust via device tags. Sensitive runs require `provider=local` plus `trusted`. Unprobed or maintenance resources never enter the execution pool. Cancellation/timeout keep their terminal verdict while owned completion releases or quarantines the resource.

Implemented real-result dashboard, report detail, JUnit XML and Allure JSON, authenticated evidence storage/download, user/key administration, audits and factual integration state. No fake run data or device streams are seeded. Backend does not execute arbitrary scripts; only registered execution Agents receive approved structured cases. React build assets belong in `src/main/resources/static`; explicit portal route fallback excludes API/asset misses.

Scheduling runs in **one central process**. The highest-precedence serialization aspect surrounds the transaction advisor, retaining its fair lock through database commit/rollback. Multiple backend replicas are unsupported: horizontal scheduling requires a database-backed distributed claim/lease implementation. This document store is intended for a small initial platform; indexed relational reporting and pagination are future scale work.

Configuration: standard `SPRING_DATASOURCE_URL`, `SPRING_DATASOURCE_USERNAME`, `SPRING_DATASOURCE_PASSWORD` with `SPRING_PROFILES_ACTIVE=postgres`; local default uses `.data/platform`. Evidence directory is `PLATFORM_EVIDENCE_DIR` (also accepts `PLATFORM_EVIDENCE_PATH`), default `.data/evidence`. `PLATFORM_TRUST_PROXY=true` trusts gateway `X-Forwarded-Proto:https`; enable only behind a controlled TLS proxy. `PLATFORM_ALLOW_INTERNAL_HTTP=true` explicitly permits RFC1918 private-network HTTP for Docker Agent/API communication; default false. This deployment allowance means private Docker traffic is HTTP, so full end-to-end internal TLS remains unverified. External non-TLS requests are rejected; localhost and public health checks support development/readiness.

Verification: `mvn package` passed the 12-test baseline. Follow-up `mvn test` covers 14 integration tests, adding quality verdict/EWMA/idempotency/manual-release role checks and parsing escaped infrastructure JUnit XML with consistent counters. Baseline coverage: unauthenticated/role denial, password/key secrecy, immediate key revocation, human approval/history/snapshots, sensitive local trust, priority/queue timeout, Agent ownership/idempotency/derived verdict, disconnect/reconnect cleanup, cancellation/execution timeout, evidence ownership+download authentication+exports, concurrent allocation across a blocked transaction commit, unprobed physical targets, remote TLS and internal transport policy. Actual browser execution, PostgreSQL runtime and portal are coordinator integration checks.

Quality extension: `GET /api/quality` returns per-case actual counts and same-commit verdict-flip EWMA (alpha 0.2). Identical nonempty commit SHA comparisons only; infrastructure-generated missing results, cancelled runs and duplicated completion messages do not contribute. Score >= 0.15 on a new flip sets a persistent reporting quarantine flag. `POST /api/quality/{caseId}/release {reason}` requires ADMIN/TESTER, a substantive human reason and writes an audit record. Later passes cannot automatically release quarantine. This flag supports review; automatic removal from CI gate suites, issue creation and escalation notifications are not implemented. Explicitly requested cases continue executing.

Not implemented in this backend baseline: real physical-device cleanup/ADB/WDA/streaming, reservation/matrix orchestration, external notifications, private AI inference/draft generation/self-healing, cloud provider execution, S3/retention automation, external IdP/account lifecycle, cross-workspace operation. Integration states expose unavailable dependencies explicitly. Allure endpoint returns structured result JSON with authenticated evidence links; generating a hosted standalone Allure UI is an external consumer concern.
